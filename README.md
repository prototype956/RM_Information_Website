# RM 队伍资料中心

采用 React、Vite、Express 与 SQLite 的队内资料共享网站。全站使用 Neon on Noir 视觉体系：哑光黑、黄绿标题与导航、紫色主要操作。通用组件来自 shadcn/ui 官方 Radix 版本，包含资料检索、收藏、文件与链接发布、预览、邀请注册和管理员管理。

## 本地运行

需要 Node.js 24 或更高版本。

```powershell
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。首次访问在服务器本机创建管理员账号，可选择添加明确标注的示例资料。没有默认账号或默认密码。

管理员在「成员与资料管理 → 成员邀请」中创建 12 位邀请码，同时可以复制邀请码或邀请链接；完整凭证只在创建时显示。邀请码采用 Crockford Base32 大写字母和数字，有效期 7 天，仅供成功注册一次，可提前撤销。

新用户在登录页点击「注册账号」，填写姓名、邮箱、10–128 位密码及邀请码；注册成功后自动登录，可立即共享资料。邀请码不区分大小写，粘贴时自动忽略首尾空白。已有的 48 位邀请凭证和邀请链接继续有效，打开邀请链接会自动填写邀请码；失效时可直接修改后重试。邮箱已注册时请点击「已有账号？去登录」。

后续使用邮箱和密码登录，无需再次填写邀请码。登录状态有效期为 7 天；当前没有邮箱验证、额外注册审核或自助密码找回功能。

## 成员与邀请管理

管理员在「成员与资料管理 → 成员列表」查看全部成员的姓名、邮箱和角色，当前账号有单独标记。支持姓名/邮箱搜索和角色筛选，每页 20 人；列表只读，不提供账号或角色修改。

邀请记录中，有效且未使用的邀请可撤销；已使用、过期和撤销的记录可点击「删除记录」，确认后永久清理。删除邀请记录不影响已经注册的成员、登录或资料，原邀请码仍不可使用。当前支持逐条删除，不提供批量清空。

成员列表与邀请记录删除接口仅允许管理员访问，不返回密码或登录凭证；无需数据库迁移。

## 构建与验证

```powershell
npm test
npm run build
npm start
```

`npm run test:members` 验证成员列表分页、搜索、筛选及邀请记录删除的确认、取消、失败重试与权限；使用临时数据库，截图可由 `QA_OUTPUT` 指定。

`npm run test:registration` 构建后使用临时数据库验证桌面和手机的登录、邀请码注册、错误恢复及新旧邀请链接；截图写入系统临时目录，可通过 `QA_OUTPUT` 指定输出目录。

`npm test` 启动隔离数据库，验证身份认证、邀请、跨站请求拒绝、真实文件上传下载、个人收藏及所有权权限。它不会修改日常数据。

电脑安装 Chrome 后，可以一键构建并运行全部界面验收：

```powershell
npm run test:ui
```

测试自动选择空闲端口，在 `artifacts/qa-data/neon-*` 中创建独立账号、数据库和附件，并在结束后关闭测试服务。日常 `data/` 不参与测试。测试目录保留，便于检查结果。`tests/browser.mjs` 保留原有 15 组业务回归；`tests/visual.mjs` 检查三种宽度、WCAG A/AA 自动规则、点击区域、焦点、错误关联与动画加载失败。

也可以对已经运行的专用测试实例分别执行 `npm run test:browser`、`npm run test:visual`，通过 `TEST_URL` 指定测试地址。`PLAYWRIGHT_PATH` 可以指定已有 Playwright 模块路径；默认使用开发依赖提供的 `playwright-core`，并启动电脑上的 Chrome。脚本拒绝连接日常使用的 5173 端口。

首页、登录、列表、详情和上传页的桌面／平板／手机截图在 `artifacts/neon/`，验收结果在 `artifacts/browser-results.json` 和 `artifacts/neon/visual-results.json`。

## 数据与配置

- 默认只监听本机 `127.0.0.1:5173`。
- `PORT`：修改端口。`HOST`：修改监听地址。
- `DATA_DIR`：数据目录，默认 `data/`。其中 SQLite 数据库与 `files/` 附件共同构成完整数据，备份时应一起保留，建议先停止服务。
- `COOKIE_SECURE=1`：HTTPS 环境启用 Secure 会话 Cookie。账号和资料接口均由服务器检查权限，附件不作为公共静态文件提供。
- 项目没有选择或绑定部署服务。如需开放队内网络，应先完成 HTTPS 和访问地址配置，并由本机管理员初始化账号。

单文件最大 50 MB，每次最多 5 个附件。PDF、图片和纯文本按需预览，其他文件提供下载。外链仅接受 HTTP/HTTPS；目标站点的可用性与权限由原站控制。资料搜索覆盖元信息，不扫描附件全文。

## 页面结构

- `/`：资料概览
- `/resources`：支持 URL 搜索、分类、标签、形式和分页的资料列表
- `/resources/new`：上传文件或分享外链
- `/resources/:id`、`/resources/:id/edit`：详情与编辑
- `/favorites`、`/uploads`：个人收藏与上传
- `/admin`：邀请与资料管理
- `/roadmaps`：学习路线列表，包含全部路线、我的学习、我创建的及管理员管理范围
- `/roadmaps/:id?node=:nodeId`：发布版阅读与个人学习进度，可分享定位节点的队内链接
- `/roadmaps/:id/edit`：路线草稿编辑、预览和发布
- `/login`：邮箱密码登录
- `/register`：填写邀请码注册
- `/join/:token`：自动填写邀请码的注册入口（兼容旧链接）

所有资料页面在未登录时显示登录界面，并保留原目标地址。站点外壳与资料模块页面分离，后续可扩展队伍官网模块。所有字体由项目本地提供，机器人结构图是原创 SVG。GSAP 装饰按需加载，手机及减少动态效果模式使用静态线稿。

## 界面维护

- `src/pages/`：登录、资料列表、详情、上传编辑、管理员页面。
- `src/components/ui/`：官方 shadcn/ui 组件源码。
- `src/components/Shell.jsx`：桌面导航、手机 Sheet 抽屉和账号菜单。
- `src/components/shared.jsx`：资料表格、查询控件、字段关联和标题动效等业务组合。
- `src/theme.css`：Tailwind CSS 4、颜色和圆角变量；`src/style.css`：页面布局与响应式规则。
- `src/fonts.css`：本地 JetBrains Mono，正文使用系统无衬线字体。

桌面顶栏可以关闭装饰动效；手机可在账号菜单中修改这一偏好。系统“减少动态效果”始终优先。机器人只执行一次 10 秒缩放，离开视口或切换后台会暂停。详情、上传、管理员页和预览器按需加载。

组件来源、适配内容和许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。此前的视觉改造不改变业务数据；学习路线模块新增接口和两张表，原有账号、资料和附件继续保留。设计参考文档只用于视觉，不包含其自由职业者业务文案。

## 学习路线使用与维护

更新依赖后重新启动本地服务（`npm install`、`npm run dev`）。启动时会增量创建 `roadmaps` 和 `roadmap_progress` 表，不需要重置数据或重新创建管理员。新增路线不会自动生成示例内容。

在“学习路线”中点击“创建路线”，填写路线设置、添加阶段与节点。电脑支持拖动位置、圆点建连和键盘移动，手机默认使用清单，并通过“添加前置节点”选择顺序。节点可以关联现有资料和 HTTP/HTTPS 外链；一键整理使用从上到下的自动布局，撤销可恢复原位置。

停止编辑约 1 秒后保存草稿，也可以手动保存。发布之前其他成员看不到草稿，更新发布之后才看到新版。保存失败会保留当前页面的内容，离开前有提醒；内容未成功保存时不要关闭浏览器。版本冲突不会覆盖服务器内容，确认重新加载会放弃当前未保存修改。

成员自行记录“未开始／学习中／已完成”，前置节点只提供学习建议。总进度按必修节点计算，选修单独计数。同一节点修改文字或位置不会清空进度；新增节点未开始，删除节点不再计入当前统计。草稿及已发布版本各保留一份，不提供历史版本回滚。

作者可编辑、撤回和删除自己的路线；管理员可管理全部路线。管理员下架后，作者无法自行重新公开；撤回或下架保留进度，永久删除连同路线学习记录一起清理。进度接口始终读取或写入当前账号，不提供其他成员看板。

每条路线最多 200 个节点、50 个阶段和 2000 条连线；每个节点最多关联 30 份资料及 30 个外链。路线接口请求体上限为 8 MiB，超限会提示减少内容；已有资料接口仍为原限制。站内资料保持原有权限，失效或无权限的引用显示“资料不可用”。

`src/roadmaps/` 包含列表、编辑器、阅读器和延迟加载画布；`server/roadmaps.js` 提供业务接口；`shared/roadmap.js` 提供前置关系与进度计算。画布或自动布局加载失败时，可以继续通过清单和表单完成核心操作。

## 当前边界

这是完整的本地运行版本，未发布到网络。未包含邮件发送、密码找回、全文检索、OCR、在线文档编辑、文件版本替换或视频托管。成员邀请通过手动复制链接分享。队名、Logo 与正式机器人素材可后续替换。

## 在线分类与可复用标签

管理员从侧栏“队伍管理 → 分类与标签管理”进入 `/admin/taxonomy`。页面分为「目录管理」「标签管理」，本地 Express 和云端 Worker 使用相同规则。

- **目录管理**：桌面左侧展开资料库和分类，右侧查看当前目录；手机逐级进入，通过顶部面包屑返回。目录固定为「资料库 → 分类」两级，可搜索名称和归属路径。
- **新增与排序**：顶部新建资料库，进入资料库后新增分类，自动填写归属。资料库及同一资料库内的分类使用上移、下移排序；搜索期间先清除搜索才能排序。
- **移动与合并**：重命名只改名称。移动分类时选择目标资料库，关联资料和路线一起移动，分类放在目标末尾；同名冲突需先重命名或选择合并。合并资料库时逐项预览下属分类将被移动或合并。
- **删除**：空目录可确认删除；非空目录需先移动内容或使用合并。标签删除会移除内容上的该标签，合并标签会替换并去重。不会删除资料文件、路线节点或个人学习进度。
- **使用情况**：点击资料数或路线数查看关联内容，每页 20 条。包含隐藏资料和路线草稿、发布版，同一路线在同一选项下只计算一次；草稿与发布版归属不同时，各自分类均能查到它。
- **标签管理**：搜索名称，筛选全部或未使用，按名称或使用量排序，每页 20 条。标签全站共享，每份资料或路线最多 12 个标签、每个最多 30 字。成员可选择已有标签，新标签仍需申请审核。
- **操作反馈**：提交期间不能重复操作；失败保留输入。遇到版本冲突时刷新选项与影响范围，再次核对并确认。新增、移动和合并后定位目标，删除后返回父级。审核入口显示待处理申请数。

继续使用稳定 ID、旧名称和旧筛选链接别名，以及现有事务和版本检查，本次无需数据库迁移。分类修改会同步资源和路线引用，受影响路线的旧编辑页面仍须处理版本冲突。

管理员接口新增 `GET /api/taxonomy/usage`（批量统计）、`GET /api/taxonomy/options/:id/content?type=resources|roadmaps&page=1`（每页 20 条）、`POST /api/taxonomy/reorder`（类型、父级、完整同级 ID 顺序及 revision）。影响接口支持 `targetId` 合并预览。普通成员不能读取管理统计、内容列表或执行排序。

运行 `npm test` 和 `npm run test:cloud` 验证本地与云端；`npm run build` 后运行 `npm run test:taxonomy` 检查桌面和手机交互。浏览器检查自行创建临时数据库，截图默认保存在临时目录，可用 `QA_OUTPUT` 指定位置；不会修改日常本地资料。本轮改版不自动部署线上。

## 选项申请与管理员审核

成员从分类字段旁的“找不到分类？申请新增”、标签搜索中的“申请新增”，或侧栏“我的选项申请”提交申请。支持资料库、分类、标签；课程申请需选择已有资料库。填写名称及可选说明后提交，待审核选项不会出现在选择列表中，也不会自动关联到当前资料或路线。

管理员进入“选项申请审核”（`/admin/taxonomy/requests`），选择通过或驳回。通过操作在同一个事务中创建选项并记录处理结果；已有同名选项会直接复用。驳回必须填写原因。课程所属资料库如果已删除，则不能通过，应驳回并请成员重新申请。

成员在“我的选项申请”（`/requests`）中查看待审核、已通过、已驳回、已撤回及审核说明，只能查看自己的申请；可撤回待审核申请，被驳回后可重新提交。审核通过后，刷新或回到资料／路线表单选择新选项。结果通过站内申请页查看，支持手动刷新和窗口重新获得焦点时刷新，无邮件通知。

重复提交自己的同名待审核申请会复用原记录；多管理员同时处理时只有第一次有效。管理员仍可直接维护选项，原有标签继续可用。服务端同时封住旧标签创建入口、资料和路线的文字标签入口，普通成员不能绕过审核。系统新增 `taxonomy_requests` 表及索引，原有数据结构和内容保持兼容。

申请接口与权限逻辑在 `server/taxonomy-requests.js`，页面在 `src/taxonomy/Requests.jsx`，复用表单在 `RequestDialog.jsx`。`npm run build` 后执行 `npm run test:requests` 可单独运行隔离浏览器检查，完整 `test:ui` 也包含此检查。截图和验证记录位于 `artifacts/requests/`；升级备份与内容核对在 `artifacts/requests-upgrade/`。
